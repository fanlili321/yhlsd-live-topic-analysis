# 客户留言分类体系 (13 类)

用于 yhlsd.com 银行螺丝钉直播选题分析。

**这个文件是分类关键词的唯一数据源**：`scripts/classify_messages.py` 在运行时直接解析本文件的
`### N. 类别名` 和 `**关键词：**` 结构，不再在脚本里维护第二份关键词列表。以后新增/修改关键词只改这一处即可，
不会再出现脚本和文档关键词对不上的问题。

## 分类体系

每类含关键词列表，采用可重叠统计（一条留言可命中多类）。关键词可以是普通子串，也可以是正则表达式
（脚本会先按子串匹配，失败再按正则匹配，所以像 `银行(?!螺丝钉)` 这种带负向断言的写法可以直接写在这里）。

## 已知的关键词精度注意事项

1. **不要用裸露的品牌词做关键词。** "银行螺丝钉"是产品名，几乎所有留言都可能提到它，如果类别1直接用
   "银行"做关键词会把海量无关留言错误地归入"银行主题基金"。已改成"银行股/银行指数/银行主题/中证银行/银行ETF"
   这类更具体的复合词。同理增加新关键词前，先想一下这个词会不会命中品牌名或者无关的高频客套话。
2. **避免超泛用词单独作为关键词。** 如"结束""定期""区别"这类词几乎任何话题都能带到，
   之前"结束"（原意是牛市结束）会命中"直播什么时候结束"这类完全无关的留言、"定期"会命中"定期直播"。
   已经把这类词换成更具体的复合短语（"牛市结束""银行定期""定期理财"等）。新增关键词时同样按这个标准把关。
3. **用真实数据验证过一轮（2026-08-06）。** 拿真实 token 拉了一次 2225 条有效留言实测，发现两类问题：
   (a) 用户会用阿拉伯数字写星级（"4.4星""5星"），光靠"五星""四星"这类中文数字关键词漏掉一大半——
   已加正则 `\d(\.\d)?\s*星` 兜底；(b) "卖了""卖掉""怎么跟""续费""主升浪"这些真实口语说法之前没覆盖，已经补上。
   这轮验证也发现真正拖累"其他"占比的大头其实不是关键词不够，是**噪音没洗干净**——企业微信里大量
   "我已经添加了你，现在我们可以开始聊天了"这类自动生成的系统消息被当成客户留言在分类，
   详见下方"清洗规则"里新增的几条。

## 清洗规则（剔除内容）

这部分是 `classify_messages.py` 里 `BAN_KEYWORDS`/`BLESSING_NOISE`/`SHORT_NOISE` 等常量的文字说明，
脚本不会解析这段文字本身——改规则要去改脚本里的常量，这里只是保持文档和实际逻辑对得上。

执行分类前必须剔除以下内容：
1. **主理人回复：** 钉大/螺丝钉/银行螺丝钉/主理人 本人的发言
2. **账号违规通知：** 包含"账号违规""功能已被限制"的文本
3. **加好友/营销：** "添加好友""加好友""查看详情""直播预告""营销"
4. **纯表情/符号：** 长度≤2 且无中文字符；或者剥掉所有 `[表情]` 标记后剩下的内容也是短噪音（如
   "[赞][赞][赞]""[good]"）
5. **无意义短文本：** 好的、谢谢、收到、嗯、哦、OK、1 等
6. **纯祝福/寒暄：** 周末愉快、静待花开、早安、晚安、新年快乐 等，没有实质问题或反馈
7. **企业微信自动系统消息（2026-08-06 用真实数据核查后新增）：** "我已经添加了你，现在我们可以开始聊天了"
   "你已添加了"（加好友回执）、"微信授权已过期"（授权失败提示）、"离开了群聊"/"加入了群聊"/"移出了群聊"
   （群成员变动通知）——这些是企业微信"其他"占比虚高的主要来源
8. **直播观看记录等追踪日志：** 形如 "260707 观看直播202601" 的纯数字/追踪码格式文本

## 输出统计维度

1. 各平台原始留言数 / 清洗后留言数 / 有效问题数
2. 高频分类 TOP5（频次+占比）
3. 每类 2-3 条代表性原文引用
4. 各渠道差异（公众号 vs 企微 vs 星球 vs 微博）
5. 本期新增/变化信号（环比上期暴增或突降的类别）
6. "其他"桶抽样（用于发现分类覆盖缺口，不进入正式排行榜，只作为改进依据）

## 报告 XML 结构

每期报告使用以下固定六段式结构，prepend 到文档最前面（倒序：最新在前）。

### 标题行

```xml
<title>AI直播选题分析</title>
<hr/>
<h1>{日期范围}</h1>
```

**标题不带"期"字。** 用户 2026-08-13 明确要求："标题里的期字删除，之后都不要出现，保留日期就可以了"——
之前是"2026-08-13 期（覆盖……）"，现在是"2026-08-13（覆盖……）"，飞书通知消息里的"{日期范围} 期已更新"
也同步去掉了这个字，保持一致。

### 一、数据范围

- 读取时间（北京时间）
- 数据来源（yhlsd.com + 四个平台）
- 留言池总量
- 各平台原始/清洗/有效问题数
- 时间跨度
- 剔除说明

### 二、高频问题排行

表格格式，含排名、主题、频次、占比四列。
仅展示 TOP10 + "其他未归类"。

### 三、代表性原问

TOP8 分类每类 2-3 条用户原话引用，标注来源平台。

### 四、渠道差异

四个平台各自的 TOP3 分类 + 渠道特征描述。
微信公众号侧重公开选题价值，企业微信侧重组合实操，知识星球侧重高阶策略，微博侧重情绪表达。

> 之前这里之后还有一段"四点五、其他未归类抽样"，把未命中13类的原文抽样直接写进文档正文。
> 用户 2026-08-06 在文档里批注要求删除，不再放进正式报告。`classify_messages.py` 仍然会算这个抽样，
> 也仍然在脚本 stdout 里打印 WARNING（占比 ≥35% 时），只是不再出现在 Feishu 文档里——
> 需要看的话直接看脚本执行日志或 `classification.json` 里的 `uncategorized_samples` 字段。

### 五、用户情绪与需求变化

基于数据的定性分析，**必须满足**（脚本生成的占位文本里也写了同样的要求，这里是权威版本）：
1. 至少引用 2 条本期「三、代表性原问」里出现过的原话作为情绪证据，不能凭空定性。
2. 如果要提变化，必须基于「二、高频问题排行」表格里的环比列（如果有）或代表性原问里能看到的实际变化，不能编造；
   首期没有环比基准时要写明"首期无对比基准"。**不要写成机械罗列"XX类别涨了X个百分点"的排行榜式清单**——
   之前这里生成过一段独立的「二点五、本期环比信号」小节，用户 2026-08-13 看到实际报告后要求去掉，原因是这类
   清单容易被统计口径的假象带偏（比如两次运行窗口有重叠、某渠道数据覆盖不稳定，会显得"全线上涨"但其实不是
   真实的关注度变化）。挑1-2个真正有原文能佐证、站得住脚的变化说清楚，比堆一串百分点数字更有价值。
3. 某类别环比变化 <1pp 的，如实写"保持稳定"，不要为了内容丰满而夸大成"显著变化"。

### 六、建议直播选题

**5 个选题方向**（用户 2026-08-06 在文档里明确批注要求 5 个，之前的"3-5个"里 3 个太少，不要减少），每个含：
- **优先级：** 高优/中优
- **选题理由：** 基于哪个高频分类、具体频次或环比数字支撑（不能只写"用户关心"这类空话）
- **核心问题：** 该选题需要回应的1-2个具体用户疑问，最好直接引用原文
- **建议结构：** 直播内容的3-4步逻辑框架

**禁止逐字复用上一期已发布过的选题方向**——某个方向本期依然成立时，必须结合本期新数据换一个新角度或新案例。

**写选题前必须先查一遍真实播出记录，避免和已经播过的期数明显重复。** 用户 2026-08-13 明确要求参考已经做过的直播。
方法（查标题级别就够，不用逐篇打开大纲正文比对）：
```bash
lark-cli api GET /open-apis/drive/v1/files --params '{"folder_token":"IscSfJSjXl1nvIdActdcwwAKnDg","page_size":30}'
```
拉第一页（最新的一批，按修改时间倒序，覆盖最近几个月）就够，扫一眼标题里"（已确认）"的那些"【第XXX期直播大纲】……"。
如果某个候选选题的主题和某一期已确认标题明显撞车（比如都是"红利指数还能不能投"这种同一个问题），换个角度或者
换成本期数据里另一个高频类别，不要原样端上去。**只是避免明显撞车，不是要逐字对比大纲正文找差异**——标题级别的
判断就够，不用为了这一步把每篇大纲文档都打开读一遍。

**不要写"选题串联逻辑"或任何暗示几个选题要串成一个系列/一期讲完的文字。** 用户 2026-08-06 明确要求："不需要有串联逻辑，
我需要的是独立的选题，提供给老板供他选择"——5个选题是并列的独立候选项，给老板挑一个用，不是要求全部串起来做。
每个选题条目就此打住（优先级/理由/核心问题/建议结构四项即可），不要在选题列表后面再加总结性的串联段落。

2. 找到 title block 的 block_id，生成新一期 XML 报告（`<hr/><hr/>` + 报告正文）
3. `lark-cli docs +update --doc KsInd8S1ko6jQgxlypncNcqanPe --command block_insert_after --block-id <title_id> --content -` 插入
